# Восстановление пароля: backend и подключение frontend

## Локальная проверка писем

По умолчанию `MAIL_MODE=file`, ссылка ведёт на
`http://localhost:5173/reset-password#token=...`. Реальные письма не отправляются.
Backend сохраняет письма в `.local/mail/*.eml` в корне проекта. Файлы содержат
рабочую ссылку; открывайте их почтовым приложением или текстовым редактором.
Каталог исключён из Git; удаляйте старые письма после проверки.

Добавьте в `.env` только нужные настройки из `.env.example`, сохранив существующий
JWT_SECRET_KEY, и перезапустите backend. Адрес фронтенда должен входить в
ALLOWED_ORIGINS. Для миграции: `.\.venv\Scripts\python.exe -m alembic upgrade head`.

Можно использовать локальный почтовый перехватчик с веб-интерфейсом:

```dotenv
PASSWORD_RESET_URL=http://localhost:5173/reset-password
MAIL_MODE=smtp
MAIL_FROM=Finance Tracker <no-reply@localhost>
SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_SECURITY=none
SMTP_USERNAME=
SMTP_PASSWORD=
```

Почтовый перехватчик должен быть запущен отдельно; backend его не устанавливает.

Для реального SMTP укажите адрес и credentials провайдера, разрешённого
отправителя MAIL_FROM, SMTP_SECURITY=starttls и порт 587 либо ssl и порт 465.
PASSWORD_RESET_URL должен вести на публичную HTTPS-страницу фронтенда.
HTTP разрешён только для localhost, 127.0.0.1 и ::1; режим file — только для
локального фронтенда. URL без query/fragment, логина и пароля. Адрес формируется
из настроек сервера, а не Host заголовка или полей запроса.

## Страница «Забыли пароль»

Вход в аккаунт не требуется. Во всех fetch укажите `credentials: "include"`.
Сначала выполните `GET /api/users/csrf` и сохраните `csrf_token` из JSON в памяти.
Браузер сам сохранит HttpOnly cookies. Origin браузер выставляет автоматически.

Отправьте `POST /api/users/forgot-password` с `Content-Type: application/json`,
`X-CSRF-Token: <csrf_token>` и телом:

```json
{"email": "alice@example.com"}
```

Ответ всегда одинаковый для существующего и неизвестного email — 202:

```json
{"message":"Если аккаунт существует, мы отправили инструкцию по восстановлению пароля."}
```

Покажите этот текст. 202 означает принятие запроса, а не гарантию доставки письма.
Поиск аккаунта и доставка выполняются после HTTP-ответа. При проблеме доставки
сервер пишет обезличенную ошибку в лог, не раскрывая email или токен клиенту.
После исправления SMTP можно запросить новое письмо с учётом лимитов.

## Страница `/reset-password`

1. Получите токен: `new URLSearchParams(window.location.hash.slice(1)).get("token")`.
2. Сохраните его только в памяти страницы и сразу очистите fragment через
   `history.replaceState(null, "", location.pathname + location.search)`.
   При перезагрузке после очистки потребуется снова открыть ссылку из письма.
3. Запросите свежий `GET /api/users/csrf`: письмо можно открыть в другом браузере,
   где нет предыдущих cookies. Вход не требуется.
4. Покажите два поля: новый пароль и повтор. Проверьте совпадение на frontend.
   Пароль должен содержать 8–128 символов; не обрезайте пробелы автоматически.
5. Отправьте `POST /api/users/reset-password` с cookies, X-CSRF-Token и JSON:

```json
{"token":"<токен из ссылки>", "new_password":"Example-new-password-123"}
```

6. На 204 не вызывайте response.json(): тело пустое. Очистите состояние
   пользователя, старый CSRF и кеш личных данных, перейдите на вход и покажите
   «Пароль изменён. Войдите с новым паролем». Автоматического входа нет.
   Перед новым входом снова получите `/api/users/csrf`.

Не сохраняйте токен в localStorage, аналитику или логи. На странице восстановления
задайте Referrer-Policy: no-referrer и не подключайте сторонние аналитические
скрипты, способные прочитать fragment. GET по ссылке не расходует токен.

## Ошибки и лимиты

| Код | Поведение frontend |
| --- | --- |
| 400 | Ссылка неизвестна, просрочена или использована: предложить запросить новую |
| 403 | Обновить CSRF, проверить разрешённый Origin; не отправлять запросы бесконечно |
| 422 | Показать ошибку email, пароля, токена или лишних полей |
| 429 | Предложить подождать; Retry-After указывает безопасную задержку в секундах |
| 503 | Показать временную недоступность; администратору проверить настройки почты |

Для этих публичных методов не запускайте refresh-сессии и не переводите
пользователя на вход до завершения восстановления.

Ограничения хранятся в БД и действуют совместно для процессов backend:
forgot — 20 запросов/IP в час и до 3 писем/email в час;
reset — 30 попыток/IP за 15 минут. Для лимита email возвращается тот же 202,
чтобы не раскрывать наличие аккаунта. Каждый принятый новый запрос письма
инвалидирует прежние ссылки пользователя. Истёкшие токены и ограничения
очищаются при последующих запросах. При размещении за reverse proxy настройте доверенные
proxy IP на сервере ASGI; не доверяйте произвольному X-Forwarded-For из интернета.

## Гарантии backend и эксплуатация

Случайный токен содержит 256 бит энтропии, действует 30 минут. В базе хранится
SHA-256 хеш; в API нет метода получения ссылки или токена. Смена пароля,
использование/отзыв всех reset-токенов и отзыв всех сессий пользователя
происходят одной транзакцией БД. При параллельных запросах выигрывает один.
Сессии других пользователей не изменяются. После смены отправляется уведомление.

Фоновые задачи выполняются внутри процесса FastAPI, без постоянной очереди:
при аварийной остановке процесса письмо может не отправиться. Для гарантированных
повторных доставок под нагрузкой потребуется очередь заданий или transactional
outbox. Текущий вариант пригоден для локальной проверки и обычного SMTP;
проверяйте обезличенные ошибки доставки и настройки реального провайдера.

Рекомендации: [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html).
