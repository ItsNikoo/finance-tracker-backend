# Категории

Все методы требуют входа в систему. Для POST, PATCH и DELETE нужны
Origin и X-CSRF-Token, как для транзакций.

| Метод | Путь | Поведение |
| --- | --- | --- |
| GET | `/api/categories` | Общие категории и личные категории текущего пользователя |
| GET | `/api/categories/{id}` | Одна доступная категория |
| POST | `/api/categories` | Создание личной категории, ответ 201 |
| PATCH | `/api/categories/{id}` | Частичное изменение своей категории |
| DELETE | `/api/categories/{id}` | Перенос транзакций в «Прочее» и удаление своей категории, ответ 204 |

Пример создания:

```json
{"name_en": "My car", "name_ru": "Мой автомобиль", "type": "expense"}
```

Ответ содержит `id`, `name_en`, `name_ru`, `type`, `is_default`.
В списке категории «Прочее» идут последними; остальные сохраняют порядок создания.
`is_default=true` означает общую категорию. Владелец определяется сервером
по сессии; передавать `user_id` или `is_default` в запросе запрещено.

PATCH принимает одно или несколько полей: `name_en`, `name_ru`, `type`.
Пустой объект, null, неизвестные поля и пустые названия дают 422.
Названия обрезаются по краям, имеют длину 1–100 символов.

Совпадение любого из названий внутри одного типа у одного владельца даёт 409.
Сравнение регистрозависимое. Разные пользователи могут создавать одинаковые
названия; личная категория может совпадать с общей.

Чужая категория возвращает 404 при чтении, изменении, удалении и попытке
использовать её в транзакции. Изменение и удаление общей категории дают 403.
При удалении личной категории её транзакции переходят в общую категорию
«Прочее» того же типа (доход или расход). Операции сохраняют все данные,
кроме category_id. Перенос и удаление выполняются одной транзакцией БД.
Если общая «Прочее» отсутствует, API возвращает 409 без изменений.
Смена типа используемой категории даёт 409; переименование разрешено.

Миграция 0007 сохраняет существующие категории как общие и добавляет недостающие
категории: расходы — Продукты, Транспорт, Жильё, Здоровье, Прочее;
доходы — Зарплата, Подарки, Прочее. При совпадении русского или английского
названия внутри типа используется существующая категория.

Применение: `.\.venv\Scripts\python.exe -m alembic upgrade head`.
Миграция 0008 добавляет общую категорию «Перевод» отдельно для доходов и
расходов. При откате версии эти категории сохраняются вместе со связями.
Миграция 0009 обеспечивает отдельные общие категории расходов «Продукты»,
«Кафе и рестораны», «Доставка», «Шоппинг». Прежняя общая «Еда» переименовывается
в «Кафе и рестораны» с сохранением ID и связанных транзакций, если целевое
название ещё не занято. Личные категории не затрагиваются. При откате версии
изменения справочника сохраняются.
Перед обновлением существующей базы сделайте резервную копию.
Миграция сохраняет идентификаторы и связи транзакций, пересоздавая таблицы
с сохранением проверки внешних ключей SQLite.

Откат к старой схеме делает все категории общими и сохраняет добавленные
категории. Если у разных владельцев есть одинаковые названия внутри типа,
откат останавливается до изменения схемы: старая схема не допускает дубликаты.
