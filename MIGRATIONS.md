# Миграции базы данных

Все команды выполняются в PowerShell из корня проекта.
Alembic использует подключение из `app/database.py`. Путь `./finance.db`
относителен текущей рабочей директории, поэтому запускайте и API, и Alembic из корня.

## Новая установка

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

При старте API таблицы больше не создаются автоматически.
Первая миграция `0001` создаёт категории, транзакции, внешний ключ,
ограничения уникальности и индекс категории транзакции. Начальные данные не добавляются.

## После изменения моделей

1. Примените существующие миграции: `alembic upgrade head`.
2. Измените модели SQLAlchemy.
3. Создайте миграцию:

```powershell
.\.venv\Scripts\python.exe -m alembic revision --autogenerate -m "add transaction description"
```

4. Проверьте `upgrade()` и `downgrade()` в новом файле `migrations/versions/`.
   Автогенерация не понимает намерение переименовать поле: она может предложить
   удаление и создание вместо переименования. Перенос и заполнение данных пишутся вручную.
   Для обязательного поля в заполненной таблице сначала предусмотрите заполнение значений.
5. Примените и проверьте:

```powershell
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m alembic check
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Коммитьте модели и новую миграцию вместе. Уже применённые миграции не переписывайте:
создавайте следующую. При добавлении новой модели импортируйте её в `migrations/env.py`,
чтобы таблица попала в `Base.metadata`.

## Версия и история

```powershell
.\.venv\Scripts\python.exe -m alembic current
.\.venv\Scripts\python.exe -m alembic history
.\.venv\Scripts\python.exe -m alembic heads
```

`current` показывает версию БД, `heads` — последние версии в файлах,
`history` — цепочку миграций. `check` ищет различия между моделями и схемой БД.

## Откат

```powershell
.\.venv\Scripts\python.exe -m alembic downgrade -1
```

Команда запускает `downgrade()` последней миграции. Откат `0001` удаляет обе
таблицы вместе с данными. Перед откатом изучите код и сделайте резервную копию.
Откат схемы не является восстановлением удалённых данных.

## Существующая база, созданная через create_all

Для текущей локальной базы схема проверена на соответствие `0001`, затем версия
зарегистрирована через `alembic stamp 0001`. Данные сохранены; резервная копия
находится в `backups/finance_before_alembic_0001.db` и исключена из Git правилом `*.db`.

`stamp` только записывает версию, не создаёт и не изменяет прикладные таблицы.
Не используйте его вместо `upgrade` на пустой или несовпадающей базе.
Для новой базы всегда выполняйте `upgrade head`.

## SQLite

Включена генерация batch-миграций для изменений таблиц SQLite. Проверка внешних
ключей сохранена. Если будущая миграция пересоздаёт таблицу, на которую ссылаются
другие таблицы, отдельно проверьте её на копии данных: порядок операций и перенос
связей могут потребовать ручной корректировки.
