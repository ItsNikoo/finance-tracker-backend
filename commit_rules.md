# Правила оформления Git-коммитов

## Формат коммита

Используем единый формат:

`{категория}: {кратко что сделано}`

Примеры:

- `feat: добавлен эндпоинт создания кошелька`
- `fix: исправлена проверка отрицательной суммы`
- `refactor: переработана логика обработки транзакций`
- `chore: добавлен gitignore`

---

## Основные категории

### feat

Используется при добавлении новой функциональности.

Примеры:

- `feat: добавлен эндпоинт пополнения баланса`
- `feat: добавлено создание кошелька`
- `feat: добавлена возможность учитывать расходы`

### fix

Используется при исправлении ошибок.

Примеры:

- `fix: исправлена ошибка изменения баланса`
- `fix: исправлена проверка суммы транзакции`
- `fix: устранена ошибка при создании кошелька`

### refactor

Используется при переработке кода без изменения его поведения.

Примеры:

- `refactor: упрощена логика обработки транзакций`
- `refactor: вынесена проверка баланса в отдельную функцию`
- `refactor: изменена структура проекта`

### test

Используется при добавлении или изменении тестов.

Примеры:

- `test: добавлены тесты для баланса`
- `test: добавлена проверка создания транзакции`
- `test: обновлены тесты API`

### docs

Используется при изменении документации.

Примеры:

- `docs: добавлена инструкция запуска проекта`
- `docs: обновлено описание API`
- `docs: добавлены примеры запросов`

### chore

Используется для технических изменений, которые не относятся напрямую к бизнес-логике.

Примеры:

- `chore: добавлен gitignore`
- `chore: добавлен env example`
- `chore: настроен линтер`

---

## Дополнительные категории

### style

Изменения форматирования кода без изменения логики.

Примеры:

- `style: исправлено форматирование кода`
- `style: применен автоформаттер`

### perf

Улучшение производительности.

Примеры:

- `perf: оптимизирован запрос к базе данных`
- `perf: уменьшено количество обращений к БД`

### build

Изменения зависимостей, сборки или инфраструктуры проекта.

Примеры:

- `build: добавлена зависимость psycopg`
- `build: добавлен Dockerfile`
- `build: обновлены зависимости проекта`

### ci

Изменения CI/CD.

Примеры:

- `ci: добавлен workflow для тестов`
- `ci: настроен автоматический деплой`

### revert

Откат предыдущего изменения.

Пример:

- `revert: отменено изменение логики расчета баланса`

---

## Рекомендации

- Писать сообщение коротко и понятно.
- Один коммит — одна логическая задача.
- Не использовать слишком общие сообщения вроде `update`, `fix`, `changes`.
- Описание после категории писать по-русски.
- Категории оставлять на английском.
- Желательно писать сообщение в прошедшем времени: `добавлен`, `исправлена`, `обновлено`.
- Если изменение большое, лучше разбить его на несколько отдельных коммитов.

## Рекомендуемый минимальный набор категорий

Для небольшого FastAPI pet-проекта обычно достаточно:

- `feat`
- `fix`
- `refactor`
- `test`
- `docs`
- `chore`
