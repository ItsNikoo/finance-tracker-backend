# Транзакции

Все операции требуют входа. Изменяющие запросы также требуют `X-CSRF-Token`;
Swagger `/docs` передаёт его автоматически после входа через Authorize.

| Метод | Путь | Действие |
| --- | --- | --- |
| POST | `/api/transactions` | Создание транзакции |
| GET | `/api/transactions` | Список своих транзакций |
| GET | `/api/transactions/{id}` | Одна своя транзакция |
| PATCH | `/api/transactions/{id}` | Частичное обновление |
| DELETE | `/api/transactions/{id}` | Удаление, ответ 204 без тела |

При создании обязательны `category_id`, `type`, `amount`, `payment_method`.
`description` необязателен, максимум 255 символов. Сумма положительная,
не более двух знаков после запятой. `type`: `income` или `expense`;
`payment_method`: `cash`, `card` или `transfer`.

PATCH принимает любое непустое подмножество полей: `category_id`, `type`,
`amount`, `payment_method`, `description`, `occurred_at`. Пропущенные поля
сохраняются; `{"description": null}` очищает описание. Для остальных полей
явный `null` запрещён. Например: `{"amount": "250.00", "payment_method": "card"}`.
Категория должна соответствовать итоговому типу: для перехода с дохода на расход
передайте одновременно `type` и `category_id` категории расходов.

`id`, `user_id`, `created_at` через PATCH изменить нельзя. Пустое тело,
неизвестные поля и некорректные значения возвращают 422; несовместимость типа
и категории — 400. Чужая или отсутствующая транзакция возвращает 404.
Изменения суммы, типа, даты и удаление сразу учитываются в балансе, доходах
и расходах за соответствующий месяц.

## Дата совершения

`created_at` — время создания записи. `occurred_at` — дата и время совершения
операции; месячный баланс учитывает именно её и границы месяца по МСК (UTC+03:00).

`GET /api/transactions/balance?month=9` возвращает баланс за сентябрь текущего
года по МСК. `month` — число от 1 до 12. Если параметр отсутствует, используется
текущий месяц. Неверный номер или формат месяца возвращает HTTP 422.

При `POST /api/transactions` можно передать `occurred_at`, например
`"2026-10-05T18:30:00+03:00"`. Если поле отсутствует, используется текущее время МСК.
Значение без смещения считается временем МСК; значение со смещением переводится
в МСК. Ответ всегда содержит `occurred_at` со смещением `+03:00`.

Для изменения даты: `PATCH /api/transactions/{id}` с телом
`{"occurred_at": "2026-09-30T23:30:00+03:00"}`. Нужны авторизация и заголовок
`X-CSRF-Token`, как для остальных изменяющих запросов. Менять можно только свои
транзакции. Пустая дата и неизвестные поля в PATCH отклоняются.

SQLite хранит `occurred_at` как местное время МСК без timezone. В миграции `0005`
старые `created_at` копируются в `occurred_at` без изменения часов и трактуются
как МСК: исходный timezone и фактическая дата операции ранее не сохранялись.
Ошибочную дату старой операции можно исправить через PATCH.

Обновление базы: `.\.venv\Scripts\python.exe -m alembic upgrade head`.
